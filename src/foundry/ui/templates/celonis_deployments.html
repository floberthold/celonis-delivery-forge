What Happens After You Create A Request

  • 1. Draft queue - The request is created in draft and linked to your selected client, project, and target metadata.
  • 2. Access validation - The agent expects a passing preflight run for the same target context before approval submission is allowed.
  • 3. Permission confirmation - You acknowledge the permission diff so reviewer and operator can see that intended changes were reviewed.
  • 4. Review handoff - Once gates pass, you submit the request for review; status changes to awaiting_approval.
  • 5. Approval outcome - A different reviewer approves (or rejects) the request. Approved requests are marked ready for supervised deployment execution.

Gate Summary And Agent Lifecycle

  • Preflight — must pass for the target tenant and Studio space via Tenant Discovery.
  • Permission Diff — reviewer must acknowledge the permission changes that will be applied.
  • Approval — a reviewer other than the request creator must explicitly approve before deployment.

When these gates are complete, the request moves from draft to awaiting_approval, then to approved. The approved state means the agent has all required evidence to continue in the supervised deployment path. If a reviewer rejects, the request returns to draft for correction and resubmission.
