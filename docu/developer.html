1) Runtime Architecture

The docs pages are rendered by UI routes and loaded from root docu/ through Jinja loader fallback logic.

2) Route & Template Layers

API + UI Routing

  • foundry.api.main mounts static files and includes all route modules.
  • foundry.api.routes.ui serves dashboard/topic pages and docs routes.
  • REST APIs stay in dedicated modules under src/foundry/api/routes/.
  • Recent route areas include quests, todos, files, KPIs, snapshots, KPI Book, GitLab, ingest, forum insights, and use cases.

Template Locations

  • Core UI templates: src/foundry/ui/templates/.
  • Documentation source: root docu/.
  • Shared shell and nav: base.html.
  • Specialized UI templates now include orchestration, todos, files, KPIs, snapshots, KPI Book, and client health pages.

3) Auth, Session, and Organization Scope

Browser Session Flow

  • /login authenticates by email/password and sets the auth cookie.
  • UI browser GET requests that hit a 401 are redirected back to login with next_path.
  • /logout clears the auth cookie and redirects to login.

Organization Selection

  • UI login auto-selects an organization from memberships, preferring owner/admin roles.
  • Most route handlers now depend on get_current_actor_with_org.
  • Missing data in UI often indicates org scoping, not absent records.

6) Documentation System

Source of truth

Keep long-form docs in root docu/ as Jinja pages extending base.html.

Visual assets

Store reusable graphics in /static/docs; use inline SVG for page-specific diagrams.

Navigation

Expose docs in top navigation to reduce onboarding friction for users and contributors.

Shared filters

Preserve Jinja filters such as clickable_url and normalized_url because multiple legacy and current templates depend on them.

7) Packaging and Runtime Expectations

  • Docker copies src/ and root docu/ into container runtime.
  • Standalone script includes docu via PyInstaller --add-data.
  • Spec file mirrors this through datas=[('docu', 'docu')].
  • /health exposes environment, database backend, and startup mode.
  • Database startup can fall back from configured Postgres to local SQLite in local/dev environments.
  • Desktop mode defaults to a LocalAppData SQLite database and writes logs to %LOCALAPPDATA%/CelonisDeliveryForge/desktop.log.
When adding new docs pages, use the same pattern and route them explicitly in ui.py.

8) Quality Checklist

  • Routes return 200 for docs pages in local and packaged runs.
  • Graphics render without external dependencies.
  • Links in docs target valid routes only.
  • No regressions in existing topic pages and dashboard flows.
  • Verify login redirect behavior and authenticated UI access after auth/session changes.
  • Recheck health output and startup mode after database or deployment changes.
