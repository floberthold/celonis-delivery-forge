1) Runtime Architecture

The docs pages are rendered by UI routes and loaded from root docu/ through Jinja loader fallback logic.

2) Route & Template Layers

API + UI Routing

  • foundry.api.main mounts static files and includes all route modules.
  • foundry.api.routes.ui serves dashboard/topic pages and docs routes.
  • REST APIs stay in dedicated modules under src/foundry/api/routes/.

Template Locations

  • Core UI templates: src/foundry/ui/templates/.
  • Documentation source: root docu/.
  • Shared shell and nav: base.html.

3) Daily Development Loop

Step Command / Action Output
Install python -m pip install -e . Editable runtime with local sources
Run API uvicorn foundry.api.main:app --reload Interactive UI + Swagger
Verify docs Open User Docs and Developer Docs Layout, diagrams, links, and content checks
Package test .\scripts\build_standalone.ps1 Desktop executable with bundled doc source

4) Documentation System

Source of truth

Keep long-form docs in root docu/ as Jinja pages extending base.html.

Visual assets

Store reusable graphics in /static/docs; use inline SVG for page-specific diagrams.

Navigation

Expose docs in top navigation to reduce onboarding friction for users and contributors.

5) Packaging Expectations

  • Docker copies src/ and root docu/ into container runtime.
  • Standalone script includes docu via PyInstaller --add-data.
  • Spec file mirrors this through datas=[('docu', 'docu')].
When adding new docs pages, use the same pattern and route them explicitly in ui.py.

6) Quality Checklist

  • Routes return 200 for docs pages in local and packaged runs.
  • Graphics render without external dependencies.
  • Links in docs target valid routes only.
  • No regressions in existing topic pages and dashboard flows.
